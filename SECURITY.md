# Security Policy

## Supported Versions

Security updates are applied to the latest release series on the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| Latest (`0.x`) | :white_check_mark: |
| `< 0.1.0` | :x:                |

## Static Analysis & Memory Safety Invariants

1. **Static Offline Execution**: The AST parser, automaton state machine, and transform passes analyze batch syntax statically in memory without ever spawning or invoking guest shell processes or executing commands.
2. **Bounds & Overflow Protection**: Substring slicing (`%VAR:~s,l%`), index parsing, and variable table evaluations enforce strict length clamping, non-negative offsets, and bounded iterations to prevent stack overflow or memory exhaustion on malicious inputs.
3. **Regular Expression & Injection Defense**: Dynamic search and substitution expressions (`%VAR:s1=s2%`) are sanitized using `re.escape()` and literal lambda replacers, eliminating regex injection and unintended backreference expansions.
4. **Credential & Environment Hygiene**: Virtual symbol tables and AST visitor instances provide complete environment isolation from the host operating system, preventing accidental disclosure of host environment variables.
5. **Caret Iteration Caps & Escape Depth Bounds**: Multi-level caret reduction algorithms enforce bounded pass iterations (default max 10 passes) with fixed-point termination guards, preventing infinite looping or memory exhaustion when processing pathological input containing recursive caret sequences.
6. **Benchmark Sandbox & Zero Dynamic Execution**: The benchmark evaluation harness (`src/benchmark/`) processes all real-world adversarial samples strictly offline in memory using static AST transformations, with zero dynamic shell dispatch, external network requests, or child process spawning.
7. **Static Path Modifier Sandboxing**: Parameter and FOR variable path modifier resolution (`%~dp0`, `%~f1`, `%~$PATH:i`) operates strictly on static lexical strings and mock directory structures by default, preventing arbitrary disk access or path traversal exploits during static analysis.
8. **Static CFG Boundary Safety & Loop Depth Clamping**: Control Flow Graph (CFG) block partitioning and dynamic jump table tracking enforce recursion limits, cycle detection via DFS back-edge discovery, and bounded BFS reachability exploration. Dynamic variable expansions in jumps are resolved against strictly isolated in-memory symbol tables without executing external processes or evaluating arbitrary shell commands.
9. **Dead Code Elimination & Static Liveness Bounds**: The Dead Code Elimination (DCE) optimization pass computes variable liveness and dead store analysis strictly in-memory using static AST traversal. Fixed-point optimization iterations are capped (default max 10 iterations) with loop convergence detection to prevent denial-of-service on cyclic or deeply nested control flows. Standard system environment variables (`DEFAULT_PRESERVE_VARS`) and explicit user symbols are safeguarded against accidental pruning, ensuring semantic equivalence of preserved code.
10. **Bounded 32-Bit Arithmetic Evaluation & Zero-Division Defense**: The arithmetic folding pass (`set /a`) operates strictly as an in-memory compiler optimization. All numerical calculations are constrained to 32-bit signed integer semantics with modulo wrapping (`[-2147483648, 2147483647]`). Division and modulus by zero operations are trapped and default to safe fallback values (`0`) without raising unhandled exceptions or triggering denial-of-service conditions. Recursive variable resolution within arithmetic expressions enforces strict recursion depth limits (`MAX_RECURSION_DEPTH = 16`) to guarantee termination on circular variable references (`a=b, b=a`).
11. **Reversal Simulation Step Bounds & In-Memory Zeroize Protocol**: String reversal and transposition simulation (`StringReversalAutomaton`, `ReversalFolderPass`) enforce strict iteration caps (`MAX_SIMULATION_STEPS = 20000`) on `FOR /L` loops, dictionary index transpositions, and pushdown stack GOTO loops, preventing CPU exhaustion or infinite loop denial-of-service attacks from crafted malicious loop bounds or step counts. Substring index extraction strictly clamps out-of-bounds start and length values to safe empty strings without throwing runtime exceptions. An explicit in-memory zeroing helper (`zeroize()`) is provided for intermediate bytearray payload buffers to prevent lingering sensitive data in memory.
12. **Quote Toggle Boundary Safety, Nested Sequence Reduction & Buffer Zeroize**: The quote normalization engine (`QuoteToggleAutomaton`, `QuoteNormalizerPass`) processes quotation toggles, escaped quotes (`^"`), and nested quote strings strictly in memory using bounded state machines. Multiple contiguous quote runs (`""""`, `""""""`) and recursive empty quote pairs are collapsed with regex matching bounds and deterministic toggle transition rules, preventing exponential backtracking or unbounded state blowup on pathological inputs. Command target lookup strips all quotes and unmasks carets to eliminate executable impersonation vectors while preserving argument boundaries for parameters with embedded whitespace or metacharacters (`&`, `|`, `<`, `>`, `^`). Memory buffers and telemetry state implement explicit zeroization (`zeroize()`) to scrub sensitive deobfuscated tokens from process memory.
13. **I/O Redirection Routing Bounds, Handle Recursion Caps & Memory Zeroize**: The I/O redirection and stream routing engine (`StreamRouter`, `RedirectNormalizerPass`, `extract_redirections`) processes stream file descriptors, handle duplication chains (`2>&1`, `1>&2`), and device sinks strictly in-memory. Handle duplication routing enforces recursion depth limits (`MAX_FORWARD_DEPTH = 10`) with visited-set cycle detection to prevent stack exhaustion or denial-of-service on circular handle chains (e.g. `1>&2 2>&1`). Token extraction caps consecutive redirection directives per command (`MAX_REDIRECTS_PER_COMMAND = 64`) to prevent unbounded token expansion attacks. Device sink classification strictly isolates DOS legacy device names (`nul`, `con`, `prn`, `aux`, `com1..9`, `lpt1..9`) without performing physical file I/O or device driver calls. All router telemetry models and active routing plans implement an explicit memory zeroization protocol (`zeroize()`) to securely wipe sensitive file paths and recorded buffer targets from memory.
14. **Invoke-DOSfuscation Concatenation Boundary Bounds, Loop Bounds & Memory Zeroize**: The Invoke-DOSfuscation concatenation decoder (`DosfuscationConcatenationDecoder`, `DosfuscationPass`) processes chained environment variables, interleaved junk variables, and scrambled parameter delimiters strictly in-memory. Fixed-point deobfuscation loops are capped at a maximum of 15 passes to prevent infinite convergence cycles. Variable chain evaluation enforces a maximum recursion depth of 10 iterations to prevent circular reference lockups (`a=%b%, b=%a%`). FOR token accumulation loop simulation enforces token count caps to prevent buffer exhaustion. Dynamic CALL trampoline unrolling verifies targets against strictly validated binary names before unwrapping. Intermediate pattern snippets, metric buffers, and decoded result structures provide explicit in-memory zeroization (`zeroize()`) to scrub reconstructed payloads from RAM.
15. **Batch Packer Payload Bounds, Anti-CFF Unrolling Caps & Memory Zeroize Protocol**: The batch packer detection and control flow de-flattening engine (`PackerSignatureDetector`, `PackerUnpacker`, `CFFAnalyzer`, `CFFLinearizer`, `DeflatPass`) processes self-extracting stubs and flattened dispatcher loops strictly in-memory. Recursive packer payload unpacking is bounded to a maximum of 5 nested layers (`MAX_UNPACK_LAYERS = 5`) and restricts decoded byte arrays to a maximum size of 10 MB (`MAX_PAYLOAD_SIZE = 10 * 1024 * 1024`) to eliminate decompression denial-of-service vulnerabilities. Control flow de-flattening and state machine traversal strictly clamp execution simulation steps (`MAX_UNROLL_STEPS = 5000`) and enforce cycle detection with visited state sets to prevent infinite unrolling loops on circular state transitions. Anti-debugging wrapper stripping sanitizes environmental guards (`%~nx0`) without touching external disk files or process hooks. All detection reports (`PackerDetectionResult`), telemetry counters (`PackerMetrics`, `DeflatMetrics`), and decrypted payload strings support comprehensive in-memory zeroization (`zeroize()`) to securely wipe unmasked scripts from memory buffers.
16. **Intermediate Representation (IR) Safety, Transpiler Injection Defense & Memory Zeroize Protocol**: The Intermediate Representation (IR) engine and target code generators (`ASTToIRBuilder`, `PythonEmitter`, `PowerShellEmitter`, `BatchTranspiler`) operate strictly in-memory without spawning subshells or executing emitted code. AST-to-IR translation enforces strict recursion depth limits (`MAX_IR_RECURSION_DEPTH = 500`) to prevent stack overflow on deeply nested parenthesized blocks or recursive statement chains. Code generation sanitizes identifiers, function names, and variable names with alphanumeric filtering, and safely escapes string constants (`repr()` escaping in Python, backtick escaping in PowerShell) to eliminate code injection vectors in generated output. Intermediate Representation programs (`IRProgram`), telemetry metrics (`IRMetrics`), and output buffers (`TranspilationResult`) implement explicit in-memory zeroization (`zeroize()`) to securely wipe sensitive deobfuscated payload representations and memory buffers.
17. **TUI Inspector Sandboxing, Terminal Width Bounds & Memory Zeroize Protocol**: The terminal AST inspector and colored diff visualizer (`ASTPipelineDebugger`, `ColoredDiffRenderer`, `ColoredASTTreeRenderer`) execute strictly in-memory without spawning child processes or interpreting unverified escape sequences. Side-by-side diff column widths are clamped to bounded ranges (`24 <= col_width <= 160`) to prevent terminal display denial-of-service or memory exhaustion on malformed terminal size queries. AST tree rendering enforces recursion depth bounds (`max_depth`) to prevent deep call stack overflows on adversarial deeply nested block trees. All diff telemetry structures (`DiffMetrics`), inspector session records (`InspectorMetrics`), and pipeline execution snapshots (`StepRecord`) implement explicit in-memory zeroization (`zeroize()`) to scrub reconstructed scripts, AST snapshots, and symbol tables from memory upon session teardown.
18. **Directory Batch Scanner Traversal Defense, File Size Bounds & Memory Zeroize Protocol**: The high-throughput batch file scanner and bulk deobfuscation engine (`DirectoryScanner`, `FileCollector`, `ScannerWorker`) strictly enforces path traversal defenses using canonical path checking (`os.path.commonpath([base_dir, target]) == base_dir`) and visited realpath tracking to prevent symlink cycle loops or arbitrary filesystem escapes. Files exceeding configurable size thresholds (`max_file_size`, default 10 MB) are skipped to prevent memory exhaustion on giant non-script files or archive bombs. Multi-encoding ingestion uses bounded decoding fallbacks with BOM stripping without invoking external shell tools. All telemetry records (`ScanItem`, `ScanSummary`), file hash digests, and error messages implement explicit in-memory zeroization (`zeroize()`) to scrub sensitive file paths and payload digests from process memory upon job completion.
19. **AST-Based Threat Intelligence & IOC Extraction Safety, Defanging & Memory Zeroize Protocol**: The AST-based malware indicator of compromise (IOC) extractor (`ASTIOCExtractor`, `IOCTransformPass`, `export_stix_bundle`) extracts IPv4, IPv6, URL, domain, file drop, and LOLBin execution indicators strictly via in-memory abstract syntax tree traversal and lexical regex parsing without connecting to external networks, resolving DNS, or executing referenced binaries. Regex patterns for IP addresses, URLs, and file drops enforce bounded length and strict structural validations to eliminate ReDoS vulnerabilities. Defanging utilities (`defang_ipv4`, `defang_ipv6`, `defang_domain`, `defang_url`) neutralize active network indicators (`hxxp://`, `[.]`) by default to prevent accidental link activation or proxy resolution in security reports. All extracted IOC items (`IOCItem`), telemetry models (`IOCMetrics`), and STIX 2.1 bundles implement an explicit memory zeroization protocol (`zeroize()`) to scrub unmasked C2 indicators and dropped artifact metadata from memory buffers upon task completion.
20. **Native C/Rust FFI Memory Safety, Pointer Validation & Volatile Zeroize Protocol**: The native C ABI interface and Rust acceleration core (`include/cmd_deobfuscator.h`, `rust/`, `src/ffi/`) enforce strict memory safety boundaries across cross-language boundaries. All C entry points (`cmd_ffi_*`) validate pointer non-nullness, input string length bounds, and UTF-8 encoding validity before memory dereferencing, returning explicit error codes (`CMD_FFI_ERR_NULL_POINTER`, `CMD_FFI_ERR_INVALID_UTF8`, etc.) rather than triggering segmentation faults or undefined behavior. Context handles (`cmd_ffi_context_t`) and result containers (`cmd_ffi_result_t`) are opaque heap-allocated pointers with deterministic lifecycles (`cmd_ffi_context_destroy`, `cmd_ffi_result_free`). Memory zeroization (`cmd_ffi_zeroize`, `zeroize_buffer`) utilizes volatile pointer writes (`std::ptr::write_volatile`) combined with compiler barriers (`std::sync::atomic::compiler_fence(Ordering::SeqCst)`) to guarantee that intermediate string buffers and deobfuscated payload memory are erased from RAM without being optimized away by compiler dead-store elimination.
21. **EBNF Conformance Validation Safety, Structural Recursion Bounds & Telemetry Zeroize Protocol**: The formal EBNF conformance validator (`EBNFConformanceValidator`, `src/ebnf/`) inspects AST structures and token sequences strictly in memory. Production matching and syntax violation checks operate without shell execution or dynamic command evaluation. AST traversal enforces maximum nesting depth limits to guard against recursion exhaustion on adversarial parenthesized blocks. All validation reports (`ConformanceReport`), violation records (`SyntaxViolation`), and rule outcome buffers support in-memory zeroization (`zeroize()`) to scrub inspected script fragments and confidential command-line tokens from process memory upon audit completion.

## Reporting a Vulnerability

If you discover a potential security issue, memory safety bug, or cryptographic flaw:

1. **Do not open a public issue** with exploit details before a fix is available.
2. Report the finding via [GitHub Security Advisories](../../security/advisories/new) or contact the maintainers directly with a minimal reproduction case.
3. We review reports promptly and coordinate fixes and release notes upon resolution.
